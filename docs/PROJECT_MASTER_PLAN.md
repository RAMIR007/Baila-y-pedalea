# Plan maestro — Baila y Pedalea

**Estado:** fundación inicial  
**Nombre:** provisional  
**Presupuesto por defecto:** 0  
**Producción:** protegida; requiere autorización explícita

## 1. Visión inicial
Explorar y desarrollar una plataforma digital que conecte actividades, experiencias o comunidades relacionadas con el baile y el ciclismo. La propuesta de valor concreta aún debe definirse con el usuario.

## 2. Fases

### Fase 0 — Fundamentos
- [x] Crear repositorio independiente.
- [x] Establecer reglas de trabajo y seguridad.
- [x] Crear documentación inicial del proyecto.
- [ ] Incorporar y revisar las instrucciones en el ChatGPT Project ya existente.
- [ ] Definir propósito, usuarios y problema principal.

### Fase 1 — Descubrimiento de producto
- [ ] Definir público objetivo y necesidades, considerando clientes de Alemania, Francia, Países Bajos y Polonia.
- [ ] Decidir cómo se relacionan baile y ciclismo dentro de la propuesta.
- [ ] Priorizar el caso de uso principal.
- [ ] Definir alcance de una primera versión (MVP).
- [ ] Identificar riesgos, requisitos legales y necesidades de privacidad.
- [ ] Definir el plan de idiomas de la web: español, alemán, francés, neerlandés y polaco como idiomas a contemplar.
- [ ] Definir cómo se mostrarán los idiomas hablados por bailarines, instructores y guías de ciclismo, sin prometer idiomas no disponibles presencialmente.
- [ ] Diseñar la internacionalización (i18n), selector de idioma y SEO multilingüe; tratar la traducción del navegador como complemento, no como única solución.

### Fase 2 — Diseño y arquitectura
- [ ] Revisar tecnologías y restricciones de alojamiento.
- [ ] Diseñar estructura de información y flujos principales.

- [ ] Documentar arquitectura y decisiones técnicas.

### Fase 3 — Implementación
- [ ] Preparar entorno local y convenciones.
- [ ] Implementar el MVP por entregas pequeñas.
- [ ] Añadir validaciones, pruebas y documentación.
- [ ] Revisar seguridad, rendimiento y SEO.

### Fase 4 — Validación y lanzamiento
- [ ] Validar con usuarios.
- [ ] Corregir problemas prioritarios.
- [ ] Preparar despliegue y monitorización sin activar servicios de pago.
- [ ] Solicitar autorización antes de cualquier publicación en producción.

## 3. Criterios de aceptación
- Cada funcionalidad responde a una necesidad acordada.
- La experiencia funciona en móvil y escritorio.
- No se exponen secretos ni datos sensibles.
- Las pruebas relevantes se ejecutan y sus resultados se documentan.
- No se generan costes sin aprobación.

## 4. Decisiones pendientes
- Propuesta de valor y público objetivo.
- País o mercado inicial y prioridad de lanzamiento de los idiomas (español, alemán, francés, neerlandés y polaco contemplados).
- Relación entre las áreas de baile y ciclismo.
- Funcionalidades prioritarias.
- Identidad de marca definitiva.
- Stack tecnológico y alojamiento, una vez inspeccionado el repositorio.
- Modelo de sostenibilidad o monetización, si aplica.
